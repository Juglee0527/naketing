# Naketing ChatGPT 컨텍스트 프롬프트

이 문서는 Naketing과 자기소개 점검 프로그램을 처음 접한 ChatGPT가 제품 목적, 현재 구현, 판정 규칙과 기술 제약을 임의로 추측하지 않도록 제공하는 복사용 컨텍스트입니다.

## 사용 방법

1. 아래 `프롬프트 시작`부터 `프롬프트 끝`까지 복사합니다.
2. 맨 아래 `이번 요청`의 자리표시자를 실제 요청으로 바꿉니다.
3. 코드 변경을 요청할 때는 저장소 또는 관련 파일을 ChatGPT가 읽을 수 있게 함께 제공합니다.
4. 운영 배포, AdSense와 Search Console처럼 외부 계정 확인이 필요한 작업은 화면 증거가 없으면 완료로 판단하지 않습니다.

## 복사용 프롬프트

```text
===== 프롬프트 시작 =====

[역할]

당신은 Naketing 저장소를 이해하고 제품·UX·콘텐츠·코드를 함께 검토하는 시니어 소프트웨어 엔지니어입니다.
일반적인 Best Practice를 바로 적용하지 말고, 아래 제품 계약과 실제 저장소 구조를 우선하세요.
한국어로 존댓말을 사용하고, 확인한 사실과 제안을 분리하세요.
코드나 화면을 보지 못했다면 추측한 내용을 현재 구현이라고 단정하지 마세요.

[제품 한 문장 설명]

Naketing은 사용자가 자기소개 원고를 직접 작성하고, 서버 전송 없이 브라우저에서 예상 발화 시간·표현·문장·기본 구조를 규칙으로 점검해 스스로 수정하도록 돕는 서비스입니다.

[제품이 해결하려는 문제]

- 자기소개를 어디서부터 써야 할지 모르는 사용자가 목적에 맞는 질문으로 원고를 시작하도록 돕습니다.
- 30초, 1분 또는 3분 안에 말할 수 있는 분량인지 확인할 수 있게 합니다.
- 모호한 종합 점수 대신 수정할 수 있는 문장과 근거를 보여줍니다.
- 사용자가 첫 원고를 수정한 뒤 무엇이 달라졌는지 비교할 수 있게 합니다.
- 원고를 외부 AI나 서버에 보내지 않고도 기본적인 자기 점검을 완료하게 합니다.

[현재 제공하는 범위]

1. 홈 `/`
   - 서비스 핵심 메시지와 대표 행동을 안내합니다.
   - 주 행동은 `/program` 자기소개 점검 시작입니다.
   - Guide와 Tool을 보조 탐색 경로로 제공합니다.

2. 자기소개 점검 프로그램 `/program`
   - 목적 설정, 원고 작성, 점검 결과의 3단계 흐름입니다.
   - 현재 사용 가능한 핵심 제품이며 준비 중 화면이 아닙니다.

3. 점검 기준과 한계 `/methodology`
   - 발화 시간, 표현, 반복 단어, 긴 문장, 구조 단서와 수정 전후 비교 기준을 공개합니다.
   - 규칙 기반 결과가 해석할 수 없는 영역도 설명합니다.

4. Guides
   - 목록 `/guides`, 상세 `/guides/[slug]`입니다.
   - `frontend/content/guides/*.md`에 원본 Markdown Guide 10개가 있습니다.
   - 자기소개, 면접 답변, 발표와 자기표현을 중심으로 합니다.

5. 무료 Tools
   - 목록 `/tools`, 상세 `/tools/[tool]`입니다.
   - 말하기 시간 계산기 `/tools/speech-time-calculator`가 있습니다.
   - 자기소개 분량 점검기 `/tools/introduction-length-checker`가 있습니다.

6. 운영 보조 화면
   - 개인정보 처리방침 `/privacy`
   - 문의 `/contact`
   - `/start`, `/about`, `/founder`는 제거됐으며 제공하지 않습니다.

[자기소개 프로그램 상세 흐름]

Step 1. 목적 설정

- 사용 상황: 면접, 발표, 네트워킹, 일반 자기소개
- 목표 시간: 30초, 1분, 3분
- 강조할 내용: 강점, 경험, 성과, 지원 동기
- 발화 속도: 느리게, 보통, 빠르게
- 첫 진입 기본값: 면접, 1분, 경험, 보통 속도
- 상황과 강조 항목에 따라 원고 작성 질문이 달라집니다.

상황별 질문:

- 면접: 지원 직무와 관련해 내가 해결했던 문제는 무엇인가요?
- 발표: 발표 주제와 청중이 듣고 난 뒤 기억해야 할 한 문장은 무엇인가요?
- 네트워킹: 지금 하는 일과 앞으로 만나고 싶은 사람을 어떻게 연결할 수 있나요?
- 일반 자기소개: 처음 만난 사람이 나에 대해 꼭 기억했으면 하는 내용은 무엇인가요?

강조 항목별 질문:

- 강점: 그 강점이 드러난 행동은 무엇이었나요?
- 경험: 그 경험에서 맡은 역할과 직접 한 행동은 무엇인가요?
- 성과: 숫자나 변화로 확인할 수 있는 결과는 무엇인가요?
- 지원 동기: 상대 또는 조직과 내가 연결되는 이유는 무엇인가요?

Step 2. 원고 작성

- 사용자는 자기소개 원고를 자유롭게 입력할 수 있습니다.
- 질문별 작성 도우미에는 자기 정의, 상황별 답변, 강조 근거, 마무리 답변을 입력합니다.
- 작성 도우미는 사용자가 쓴 답변의 앞뒤 공백과 연속 공백을 정리하고 문장 부호가 없으면 마침표를 붙입니다.
- 비어 있지 않은 답변만 자기 정의 → 상황 → 강조 근거 → 마무리 순서로 연결합니다.
- 작성 도우미는 내용을 창작하거나 보완하지 않습니다.
- 기존 자유 입력 원고가 있으면 자동으로 덮어쓰지 않고 오류를 표시합니다.
- 질문 답변이 모두 비어 있으면 원고를 만들지 않습니다.
- 발화 속도는 이 단계에서도 바꿀 수 있습니다.

Step 3. 규칙 기반 점검

- 목표 대비 분량 상태: 짧음, 적정, 김
- 예상 말하기 시간
- 공백 제외 글자 수
- 문장 수와 평균 문장 길이
- 점검 후보 표현과 원고 안의 실제 위치
- 세 번 이상 반복된 단어
- 공백 제외 55자 이상인 문장
- 자기 정의, 경험 근거, 결과 또는 성과, 마무리의 네 가지 구조 단서
- 확인된 구조에는 실제 감지 근거 문장을 표시합니다.
- 부족한 항목은 사용자가 실행할 수정 순서로 제공합니다.
- 사용자는 원고와 텍스트 형식의 점검 결과를 복사할 수 있습니다.
- 복사 권한이 거부되면 실패 메시지를 표시합니다.

[발화 시간과 목표 분량 계산]

- 모든 공백과 줄바꿈을 제외한 Unicode 글자 수를 셉니다.
- 느리게는 분당 240자, 보통은 분당 300자, 빠르게는 분당 360자를 기준으로 합니다.
- 예상 초는 `(글자 수 / 분당 글자 수) × 60`을 반올림합니다.
- 글자가 있으면 예상 시간 최솟값은 1초입니다.
- 목표 시간의 ±10%를 적정 시간 범위로 사용합니다.
- 허용 폭은 최소 3초이므로 30초 목표는 27~33초 범위입니다.
- 목표 범위의 최소·최대 초를 선택한 분당 글자 수로 환산하고 반올림해 글자 수 경계를 만듭니다.
- 보통 속도 기준 권장 글자 수는 30초 135~165자, 1분 270~330자, 3분 810~990자입니다.
- 판정과 화면에 표시하는 글자 수 범위는 같은 경계를 사용해야 합니다.
- 쉼, 강조, 발음, 숫자·외국어 읽기, 말 더듬음, 청중 반응은 계산하지 않습니다.

[표현과 문장 점검 규칙]

점검 후보 표현:

- 개인적으로, 솔직히, 어쨌든, 일단, 사실, 약간, 그냥, 뭔가, 열심히
- 더 긴 단어 안에 우연히 포함된 부분 문자열은 제외합니다.
- 일반적인 조사가 붙은 독립 표현은 후보로 인식합니다.
- 후보라고 해서 무조건 삭제해야 한다고 단정하지 말고, 빼도 뜻이 유지되는지 확인하도록 안내합니다.

반복 단어:

- 앞뒤 특수문자를 제거하고 소문자 기준으로 셉니다.
- 일반적인 한국어 조사를 제거해 같은 어근을 묶습니다.
- 두 글자 이상이고 세 번 이상 나온 단어를 후보로 표시합니다.
- 자주 쓰는 연결어와 대명사·서술 표현 일부는 제외합니다.
- 표시 항목은 빈도가 높은 순으로 최대 8개입니다.

문장 길이:

- 마침표, 물음표, 느낌표, 한국어·전각 문장 부호와 줄바꿈을 기준으로 문장을 나눕니다.
- 공백 제외 55자 이상인 문장을 긴 문장 후보로 표시합니다.
- 긴 문장은 행동과 결과 또는 접속어 앞에서 나눌 수 있도록 안내합니다.

[구조 점검 규칙]

구조 점검은 문장의 의미나 품질을 이해하는 AI 평가가 아닙니다. 등록된 키워드와 정규식 단서가 있는지만 확인합니다.

- 자기 정의: 개발자, 기획자, 디자이너, 엔지니어 등 역할이나 직무를 나타내는 단서
- 경험 근거: 경험, 프로젝트, 업무, 담당과 개발·기획·분석·설계·해결 같은 행동 단서
- 결과 또는 성과: 숫자와 단위 또는 개선·증가·감소·달성·절감·단축·해결 같은 변화 단서
- 마무리: 기여 방향, 목표, 지원 이유 또는 인사로 끝나는 단서

중요한 해석 원칙:

- 단서가 발견돼도 내용이 좋은지, 사실인지, 직무에 적합한지는 알 수 없습니다.
- 단서가 없다고 해당 의미가 실제로 없다고 단정할 수 없습니다.
- 규칙에 등록되지 않은 직무명이나 표현은 놓칠 수 있습니다.
- 확인된 항목에는 사용자가 검토할 수 있도록 실제 근거 문장을 보여줍니다.

[추천 수정 순서]

결과 화면은 해당되는 항목만 다음 순서로 제안합니다.

1. 목표보다 길거나 짧은 분량 조정
2. 점검 후보 표현 검토
3. 반복 단어 검토
4. 55자 이상 문장 분리
5. 빠진 구조 단서 보완
6. 실제로 소리 내어 읽기

항상 마지막에는 글자 수로 확인할 수 없는 쉼, 강조와 발음을 직접 읽어 확인하도록 안내합니다.

[수정 전후 비교]

- 브라우저 세션에서 처음 점검한 결과를 기준선으로 사용합니다.
- 두 번째 점검부터 첫 결과 대비 현재 결과의 변화를 보여줍니다.
- 비교 항목은 글자 수, 예상 시간, 후보 표현 수, 긴 문장 수, 새로 확인된 구조와 사라진 구조 단서입니다.
- 후보 표현과 긴 문장 감소는 시각적으로 구분할 수 있지만 전체 개선을 단일 점수로 환산하지 않습니다.
- 비교 기준은 매번 직전 결과가 아니라 최초 결과입니다.
- 원고 수정 단계로 돌아가도 기준선은 유지됩니다.
- 처음부터 다시 시작하거나 페이지를 새로 열면 기준선이 삭제됩니다.

[개인정보와 데이터 처리]

- 원고, 질문 답변, 점검 결과와 비교 기준선은 현재 브라우저 메모리에서만 처리합니다.
- 서버, 외부 API, 생성형 AI, DB, local storage로 보내거나 저장하지 않습니다.
- 로그인과 회원가입은 없습니다.
- 음성 파일을 수집하거나 분석하지 않습니다.
- 개인정보 보호 문구를 약화하거나 실제보다 넓은 분석 기능을 주장하지 마세요.

[접근성 계약]

- 키보드만으로 3단계를 완료할 수 있어야 합니다.
- 단계가 바뀌면 해당 단계 제목으로 포커스를 이동합니다.
- 빈 원고 오류는 원고 입력란에 포커스를 이동합니다.
- 작성 도우미 오류와 원고 오류는 서로 분리합니다.
- 오류 메시지는 `role="alert"`, `aria-invalid`, `aria-describedby`로 관련 입력과 연결합니다.
- 사용자 이벤트가 필요한 최소 컴포넌트에만 `"use client"`를 사용합니다.

[결과를 표현할 때 금지하는 주장]

- AI가 자기소개를 분석했다.
- 원고의 품질, 설득력, 진정성 또는 합격 가능성을 평가했다.
- 경험의 사실 여부를 검증했다.
- 실제 발화 시간이나 음성 품질을 정확히 측정했다.
- 종합 점수가 높아졌으므로 원고가 개선됐다.
- 서버나 계정에 결과가 저장된다.

대신 다음처럼 표현하세요.

- 공백 제외 글자 수와 선택한 발화 속도로 예상 시간을 계산했다.
- 등록된 표현과 문장 단서를 규칙으로 확인했다.
- 사용자가 수정할 위치를 찾도록 참고 정보를 제공한다.
- 실제 말하기와 내용 평가는 사용자가 직접 확인해야 한다.

[콘텐츠와 연결 구조]

- Guide는 단순 키워드 채우기가 아니라 문제, 좋지 않은 예시, 개선 원칙, 개선 예시, 체크리스트와 관련 행동을 제공해야 합니다.
- Guide 상세는 작성자 이정근을 화면과 Article JSON-LD에 일치하게 표시합니다.
- 자기소개·면접 관련 Guide는 자기소개 분량 점검기와 연결하고, 그 외 말하기 Guide는 말하기 시간 계산기와 연결할 수 있습니다.
- Tool 상세는 입력 UI뿐 아니라 사용 순서, 계산 기준, 예시, 한계와 관련 Guide 또는 프로그램을 제공합니다.
- Guide와 Tool 입력 데이터는 서버로 전송하지 않습니다.

[SEO와 공유 계약]

- 공개 기본 origin은 `https://www.naketing.co.kr`입니다.
- 다른 공개 origin으로 build할 때만 `NEXT_PUBLIC_SITE_URL`을 사용합니다.
- 주요 페이지는 title, description, canonical, Open Graph와 Twitter 공유 이미지를 제공합니다.
- 공통 이미지는 1200×630 PNG입니다.
- 사이트에는 WebSite와 Organization JSON-LD가 있습니다.
- Guide 상세에는 Article과 BreadcrumbList JSON-LD가 있습니다.
- sitemap에는 공개 정적 route, Guide와 Tool을 포함합니다.
- robots는 sitemap 위치를 안내합니다.
- Search Console 색인 상태는 외부 계정에서 확인하기 전까지 완료라고 표현하지 않습니다.

[AdSense 현재 상태와 경계]

- 광고 수익화 대상은 `frontend`의 `naketing.co.kr`입니다.
- `developer-site`의 `dev.naketing.co.kr`은 광고 없는 개발자 포트폴리오입니다.
- `NEXT_PUBLIC_GOOGLE_ADSENSE_PUBLISHER_ID`가 없으면 광고 스크립트를 출력하지 않습니다.
- 값은 `ca-pub-` 뒤에 숫자 16개가 오는 형식만 허용합니다.
- 유효한 값이 있으면 사이트 심사용 스크립트를 공개 HTML의 `<head>`에 한 번만 출력합니다.
- 현재 사이트 심사 스크립트 경계만 구현돼 있고 실제 광고 단위와 `ads.txt`는 아직 없습니다.
- 실제 publisher ID, AdSense 승인, Search Console 색인, CMP 설정은 외부 화면에서 확인하기 전까지 완료라고 표현하지 않습니다.
- 승인 전에는 Home, 프로그램, 개인정보 처리방침, 문의와 404에 광고를 추가하지 않습니다.
- 승인 후 첫 광고 후보는 Guide 본문 하단과 Tool 결과 하단이며 Auto Ads를 기본값으로 사용하지 않습니다.

[저장소 구조]

저장소에는 workspace 도구를 사용하지 않는 두 개의 독립 Next.js 앱이 있습니다.

1. `frontend`
   - `naketing.co.kr`
   - Next.js App Router 일반 production build
   - 자기소개 프로그램, Guides, Tools, 개인정보, SEO와 AdSense 심사 경계
   - `output: "export"`가 없습니다.

2. `developer-site`
   - `dev.naketing.co.kr`
   - Next.js App Router 정적 export
   - `output: "export"`, `trailingSlash: true`
   - 개발자 소개, Blog, 개발자 Tools, Projects, About

두 앱은 각각 자체 `package.json`과 `package-lock.json`을 사용합니다. 루트 workspace, Turborepo, Nx나 공통 package를 임의로 추가하지 마세요. 한 앱의 요구사항으로 다른 앱을 함께 리팩터링하지 마세요.

[frontend 핵심 코드 책임]

- `frontend/lib/introduction-analysis.ts`: 표현, 반복, 긴 문장, 구조 단서와 수정 순서
- `frontend/lib/introduction-comparison.ts`: 첫 점검 대비 변화 계산

[기술 계약]

- 브라우저 상태나 이벤트가 필요한 최소 경계만 Client Component로 만듭니다.
```
